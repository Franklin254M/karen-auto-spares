# Karen Auto Spares sales system

This workspace contains both versions:

- `index.html`, `app.js`, and `styles.css` are the online Supabase version.
- `offline/index.html` is the local-only version and stores data in this browser.

Use the online version when multiple laptops need shared records and secure accounts. Use the offline version when the shop needs a self-contained local workspace without a database connection.

## Setup

1. Create a Supabase project.
2. Open the Supabase SQL Editor and run `supabase.sql`.
3. Create the admin and sales-agent users under Authentication > Users.
4. Change the administrator profile role to `admin` using the SQL comment at the bottom of `supabase.sql`.
5. Replace `YOUR_SUPABASE_URL` and `YOUR_SUPABASE_ANON_KEY` in `app.js` with the project values from Supabase Settings > API.
6. Serve this folder over HTTP. From this workspace, run `python -m http.server 4173`, then open `http://localhost:4173/` for online or `http://localhost:4173/offline/` for offline.
7. Deploy the invitation function with the Supabase CLI: `supabase functions deploy create-sales-agent`.

For a public website, upload the `online` folder to Netlify, Vercel, or GitHub Pages. Then add the public HTTPS address in Supabase **Authentication > URL Configuration > Redirect URLs** and set it as the Site URL. The local `http://localhost:4173/` address is only for testing.

Before using **Team access**, deploy the function and set its service key:

```powershell
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase secrets set SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVICE_ROLE_KEY
supabase functions deploy create-sales-agent
```

Never put `SUPABASE_SERVICE_ROLE_KEY` in `app.js`, a public website, or a Git repository.

If the database was already created before supplier support was added, run this once in Supabase SQL Editor:

```sql
alter table public.products add column if not exists supplier text;
```

For returns and warranty cases on an existing database, run this once in Supabase SQL Editor:

```sql
create table if not exists public.returns (
  id bigint generated by default as identity primary key,
  product_id bigint not null references public.products(id),
  receipt_no text,
  agent_id uuid not null references public.profiles(id),
  agent_name text not null,
  qty integer not null check (qty > 0),
  type text not null check (type in ('Return', 'Warranty')),
  reason text not null,
  notes text,
  status text not null default 'Open' check (status in ('Open', 'Approved', 'Rejected', 'Resolved')),
  created_at timestamptz not null default now()
);

alter table public.returns enable row level security;
create policy "users read permitted returns" on public.returns for select to authenticated using (public.is_admin() or agent_id = auth.uid());
create policy "agents create returns" on public.returns for insert to authenticated with check (agent_id = auth.uid());
create policy "admins manage returns" on public.returns for update to authenticated using (public.is_admin()) with check (public.is_admin());

create or replace function public.record_return(
  p_product_id bigint,
  p_receipt_no text,
  p_qty integer,
  p_type text,
  p_reason text,
  p_notes text default null
)
returns public.returns
language plpgsql security definer set search_path = public
as $$
declare sale_total integer; agent_profile public.profiles; return_record public.returns;
begin
  if auth.uid() is null then raise exception 'Authentication required'; end if;
  if p_qty is null or p_qty <= 0 or p_qty <> trunc(p_qty) then raise exception 'Quantity must be a positive whole number'; end if;
  if p_type not in ('Return', 'Warranty') then raise exception 'Invalid return type'; end if;
  select * into agent_profile from public.profiles where id = auth.uid();
  if agent_profile.id is null then raise exception 'Profile not found'; end if;
  if p_receipt_no is not null then
    select coalesce(sum(qty), 0) into sale_total from public.sales where receipt_no = p_receipt_no and product_id = p_product_id and (public.is_admin() or agent_id = auth.uid());
    if sale_total < p_qty then raise exception 'Return quantity exceeds the recorded sale'; end if;
  end if;
  insert into public.returns (product_id, receipt_no, agent_id, agent_name, qty, type, reason, notes)
  values (p_product_id, nullif(trim(p_receipt_no), ''), auth.uid(), agent_profile.full_name, p_qty, p_type, trim(p_reason), nullif(trim(p_notes), ''))
  returning * into return_record;
  return return_record;
end;
$$;

revoke all on function public.record_return(bigint, text, integer, text, text, text) from public;
grant execute on function public.record_return(bigint, text, integer, text, text, text) to authenticated;
```

The browser must use the Supabase anon key only. Never put a service-role key in frontend code.

For the first administrator, create the Auth user with the administrator email in Supabase Dashboard, set its password there, then run this SQL to grant the role:

```sql
update public.profiles
set role = 'admin', full_name = 'Franklin Mutua'
where id = (select id from auth.users where email = 'franklinmutua254@gmail.com');
```

The password is intentionally not written in this repository. Use a strong password in Supabase Auth and keep it private.

## Role behavior

- `admin`: overview, shared inventory, purchasing, customers, reports, and all sales.
- `sales_agent`: sales and receipts for that agent.

Administrators can use **Purchasing control** to see low-stock parts and **Receive new stock** to add a new part with its quantity, incoming cost, optional supplier, and optional image URL. Existing products can be updated with **Edit** in Inventory. Administrators and sales agents can open **Overview** for sales profit comparisons and **Returns & warranty** to record cases.

Administrators can open **Team access** in the online app and invite a sales agent by name and email. The invitation function uses the Supabase service-role key only in Supabase's server environment; it is never placed in `online/app.js` or GitHub.

The database policies in `supabase.sql` enforce the role boundary; the frontend navigation is not the security boundary.

The offline version is included in `offline/` and continues to use local browser storage independently.
